# 通知投递

在「系统设置 → 通知」管理渠道并查看投递记录。摘要消息按原始条目顺序组装，只有实际进入成功请求的条目才计为已送达，剩余条目继续进入后续批次。

如果 Telegram 群只需知道有新记录，可以在该渠道开启「隐私简报」。消息会显示本次条数、已有记录的编号和严重性，省略任务名、标题、摘要、资产和链接。**即使没有配置详情链接，群成员也能看到编号。** 未识别的级别统一显示为 `unknown`。这个选项对该渠道的实时、汇总、状态变更和测试通知均生效，默认关闭。

飞书与 Lark 机器人使用完整 JSON 请求体计量大小，包含卡片标题、正文、按钮、URL、JSON 转义和启用时的时间戳与签名。按[飞书自定义机器人文档](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)的 20 KB 限制，应用采用更保守的 20,000 字节预算；多字节文本和需要转义的字符均按实际序列化结果计量。

打包先检查完整批次是否可发送，再选择能容纳的条目前缀。若单条内容或必要元数据也无法容纳，请求会在发送前返回明确错误，并保留未送达状态；可在投递记录中检查失败原因，缩短条目或链接后重试。
