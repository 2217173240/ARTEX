# 能力就绪与局部降级

ARTEX 的核心依赖保障服务的数据和权限边界；可选能力根据当前配置、批准状态和实际可用性独立装配。可选能力缺失时，其他功能继续工作。恢复配置或服务后，后续操作重新检查并启用可用能力。

| 依赖或能力 | 所需条件与故障范围 |
| --- | --- |
| PostgreSQL、服务认证初始化 | 服务核心依赖。无法建立可靠的数据或认证边界时，启动返回明确错误。 |
| 模型提供方 | 调用模型的操作需要有效配置及可用提供方；缺少配置不会阻止管理界面和配置操作。 |
| MCP 服务 | 每个服务独立核对启用、管理员批准、配置版本、Agent 可见性和实际连接。不可用的服务在本次装配中跳过并记录原因，其他工具继续装配。 |
| 技能目录、可选采集工具 | 按实际加载和启用状态注册；缺失或关闭时，只影响使用相应能力的操作。 |
| 工具授权目录 | 执行工具所需的安全条件。读取失败必须停止该次工具装配，不能将目录不可用解释为全部工具获准。 |
| 指定会话的历史 | 恢复操作的必要上下文。读取或解码失败返回带会话标识的包装错误，保留原始文件并停止该次恢复。新会话及显式关闭持久化的操作保持各自语义。 |

## MCP 初始化与恢复

每个 MCP 在当前操作中使用独立的 90 秒初始化预算，覆盖授权检查、连接握手和工具发现；父操作取消也会终止初始化。失败客户端立即关闭，本次装配继续处理其他服务。HTTP 会话删除和 SSE 读取器关闭可能额外消耗各自有限的清理时间。

初始化上下文只管理初始化工作。成功返回的客户端由现有操作清理函数持有，后续工具调用使用自己的上下文。调用前继续核对批准及配置版本，停用、撤销或变更后旧客户端不能继续使用权限。

当前装配逐个初始化服务，多个不可用服务可能累计等待各自预算。后续操作重新检查实际状态；不永久缓存失败，也不进行无条件重试。

## 变更与验证要求

审阅能力变更时检查：部分可用、全部可选能力缺失、移除、恢复、父操作取消和资源释放。使用真实的隔离依赖验证实际路径，区分已经执行的场景与未覆盖范围。成功注册不等于授权成功，扫描通过也不代替运行时权限检查。

MCP 回归使用隔离 PostgreSQL 的批准记录、真实操作系统进程和官方 MCP SDK 服务验证初始化超时、取消、健康客户端生命周期及后续恢复。官方 SDK 服务需要显式提供测试入口；未配置时明确跳过，不能将跳过记为已经验证。其他权限测试及完整质量检查继续执行。
