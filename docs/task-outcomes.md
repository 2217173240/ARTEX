# 任务结果度量

任务详情「总览」提供结果卡，归档列表可打开任务结果。卡片按需读取，支持手动刷新；读取失败只影响结果卡，可重试。

`GET /api/tasks/{id}/outcome` 汇总当前任务的产出与已记录消耗，查询在同一只读数据库快照中选择热数据或冷归档，避免归档切换时重复计数。

| 指标 | 计量范围 |
| --- | --- |
| 发现 | 本任务拥有的独立 finding 行，不含继承来源；不等于归并案例数 |
| 已确认等级 | 状态为 confirmed、resolved、fixed 的严重等级分布；未知等级单列 |
| 复测 | 本任务 finding 的全部复测尝试；结论只统计 completed 尝试，重复复测分别计数 |
| 模型调用与 token | 已保存的 completion 调用账本，包含被记录的失败调用；内部 HTTP 和空响应重试无法逐次区分 |
| 工具与技能缺失 | 精确归属当前任务的账本；只有 task_id 缺失时才使用 exploration_id |
| 经过时间 | 首次运行至完成或本次读取的墙钟时间，包含暂停和等待；从未运行或完成时间缺失时未知 |
| 费用 | 未采集价格与结算调整，不能从 token 数推断实际费用 |

模型、工具和技能账本不包含独立复测会话的消耗。提供方未返回 usage 时，现有账本无法区分未知与零；未写入的账本不能由此接口恢复。

明确归属单个任务的自动触发会话也记录到该任务的模型账本。跨任务合并的触发会话保留 Agent 归属，用量不分配到任一任务；历史缺失归属不作回填。归档结果只包含制作快照时已保存的调用，独立触发会话随后完成的消耗不补写冷归档快照。

需要核对单次调用时，可使用[按会话诊断模型用量](llm-usage.md)中的轻量账本接口；关闭正文录制后仍可查询已保存的会话计量。

新归档包保存任务结果快照和真实复测记录。还原后重新查询实际热数据。独立复测会话保留在原实例；服务端归属绑定核对会话、复测、finding 和任务，无法确认来源时解除引用并记录警告。运行或排队的复测需要先完成或停止，随后才能归档任务。

新归档使用格式 v4，继续读取 v1–v3。历史归档缺少可靠计量维度时返回 `partial` 与 `unavailable`，界面显示不可用范围；历史缺失不会因再次运行复测而变为完整历史。归档包仍用于同一实例内恢复，不是可导入空数据库的完整备份。
